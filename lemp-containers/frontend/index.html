Below, you can see the 3 main pods generated for the webpadge. After deleting one backend pod, a new pod is generated after a few seconds. I use the curl command to visit the webpage on cli and i can watch the visits increase as I continued copying the command. Deleting the backend pod could erase the sites data such as visits.

As you can see this does not occur and visited data has not been erased. This occurs because db-deployment.yaml declares a Persistant Storage under the name mysql-data.

Apply developing the containerised app, which can be seen on my giyhub: https://github.com/Ben-Ifeanyi-Donnelly/Rathi-Containerised-app, I applied the yaml files the lecturer provided.
Below I applied them to Openshift's API server. The yaml files instruct on how much pods are kept active at a time for the frontend and backend. That's why from earlier, once one is destroyed, OpenShift's API is watched and based on instructions, it will build back however many replicas I have set it for. I had three backend replicas so self healing happened within seconds after I deleted the pod.
